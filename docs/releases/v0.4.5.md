# car-go-clean v0.4.5

## Status summary

Restores total bytes recovered (all time) to the default concise `status` view,
using the same successful, measured cleanup accounting as the verbose view.

## Cleanup failure maintenance

`status` now separates historical failures into targets that still contain entries,
unverified paths, and targets observed missing or empty. The last run's error count
remains the actual number of failures in that run. `status --verbose` and `health`
show each historical failure's current observation and any retry deadline.

Observations are read-only snapshots, refreshed on each diagnostic request. They
never authorize deletion or erase history. Missing/empty targets that gain files
become actionable again. Symlinks, unreadable paths, concurrent changes, excluded
paths, protected roots, and paths outside current scope remain unverified.

After two cache-marker failures, unreviewed cleanup cycles defer further attempts
for seven days from the last failure while the marker is still missing/invalid and
the target has no newer top-level modification. A valid marker or top-level write
ends the delay early. This is bounded backoff, not a full recursive change detector:
nested writes or toolchain changes may wait for the deadline. A fresh reviewed run
can retry sooner, subject to all existing identity, scope, and activity checks.
Other Cargo errors are not deferred. Deferred attempts count as skipped, not as
successful cleanups or new errors; status continues to show them needing attention.

## Compatibility and safety

- Existing JSON history (`unresolved_cleanup_failures`) retains its meaning and
  records. `cleanup_failure_observations` is an additive diagnostic array; each
  entry contains `path`, `state`, `reason`, and optional Unix-seconds `retry_after`.
- Exit-code rules, discovery, cleanup authorization and Cargo's marker safeguards
  are unchanged. No marker is created, no artifact is deleted by reconciliation,
  and no recovered bytes are attributed to missing or empty directories.
- No configuration or database migration is needed; old history is classified
  immediately. Downgrading retains the complete audit history but resumes the old
  retry cadence. This release does not include the paused 0.5.0 discovery work.
