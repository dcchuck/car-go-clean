# car-go-clean v0.4.4

## Improvements

`status` now shows a concise summary: service state, discovery state, cached
projects, the last run's cleanup/error counts, historical unresolved failures,
the last review summary, and scheduling information. Incomplete discovery and
service warnings remain visible.

Use `car-go-clean status --verbose` for the full diagnostic view, including
failure paths and remediation, protected roots, policy identity, and review
details. Pass the same `--config` and `--state-dir` options when inspecting a
nondefault installation.

The last run's error count and unresolved history count describe different
things. History includes paths with no later successful measured cleanup; it
does not establish whether those paths still exist or currently need attention.
This release labels that distinction without erasing or reconciling records.

## Compatibility

- `status --json` is unchanged; adding `--verbose` has no effect on JSON.
- Exit codes and their meaning are unchanged, including `status --refresh`.
- Human-readable default output changes intentionally. Scripts should use JSON;
  `--verbose` retains the previous detailed text view.
- `health`, cleanup, retries, discovery, configuration, database schema, and
  scheduled daemon behavior are unchanged. No migration is required.
- This release does not repair missing Cargo cache markers, change macOS signing,
  or introduce any of the planned 0.5.0 discovery features.

Publication and installed-daemon upgrades are separate operator actions.
